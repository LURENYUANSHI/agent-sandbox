## v0.2.0 Changes Summary

### Bugs Fixed: 6
- Race conditions in concurrent sandbox execution
- Policy evaluation edge cases with wildcard matching
- Trace recorder resource leaks on close
- API error response inconsistencies
- Config validation gaps
- WebSocket connection cleanup issues

### New Features
- **JWT Authentication** — Token-based API auth middleware with configurable secret and expiry
- **Rate Limiting** — Per-IP rate limiter with configurable burst/rate and automatic cleanup
- **Input Validation** — Comprehensive request validation for sandbox creation, action execution, and policy submission
- **Dashboard API** — Stats and recent activity endpoints for the web dashboard
- **WebSocket Integration** — Real-time trace streaming to React dashboard components
- **Centralized Configuration** — All hardcoded values replaced with configurable options (env vars, config files)
- **Resource Limits** — Disk usage and process count enforcement per sandbox
- **Persistent Audit Logging** — SQLite-backed audit log with query API for compliance
- **CI/CD Pipeline** — GitHub Actions workflows for test, lint, web build, Docker, and releases

### Test Coverage Improvement
- From ~78% average to 84.9% average across core packages
- Policy engine: 78.6% → 99.1%
- Executor: 69.0% → 81.7%
- Test count: 42 → 225 (5.4x increase)

## Known Limitations

1. **OS-level sandbox isolation not fully wired** — Linux namespaces/cgroups and Windows job objects are scaffolded but not enforced at runtime
2. **No role-based access control** — JWT auth exists but all tokens have the same permissions
3. **No API documentation generation** — No Swagger/OpenAPI spec auto-generated from code
4. **No GitHub issue/PR templates** — Missing structured templates for bug reports and feature requests
5. **CLI has 0% test coverage** — cmd/sandbox and cmd/server main packages are untested
6. **SQLite-only trace storage** — No option for distributed trace backends (Jaeger, Tempo)
7. **No log rotation for audit logs** — Audit SQLite database will grow unbounded
8. **Web dashboard lacks E2E tests** — React components are not tested with Playwright/Cypress
9. **Windows-only development validated** — Linux-specific features untested in CI

## Recommendations for v0.3.0

### Priority 1: Production Readiness
1. **Wire OS-level isolation** — Implement Linux namespace/cgroup sandboxing and Windows job objects
2. **Role-based access control** — Add user roles (admin, operator, viewer) to JWT claims
3. **API documentation** — Generate OpenAPI spec from Gin routes, serve Swagger UI
4. **Log rotation and retention** — Add configurable retention policy for audit logs

### Priority 2: Testing & Quality
5. **CLI test coverage** — Add integration tests for CLI subcommands
6. **Web E2E tests** — Add Playwright tests for critical dashboard flows
7. **Cross-platform CI** — Run tests on both Linux and Windows in GitHub Actions
8. **Load testing** — Benchmark API server under concurrent sandbox workloads

### Priority 3: Ecosystem
9. **Agent SDKs** — Python and TypeScript client libraries for sandbox API
10. **Distributed tracing backend** — Support Jaeger/Tempo as alternative to SQLite
11. **Plugin system** — Allow custom policy rules and executor extensions
12. **Kubernetes operator** — Deploy sandboxes as K8s pods with CRDs
