## v0.3.0 Changes Summary

### New Features
- **MCP Server** — Model Context Protocol server for AI agent integration (Claude Desktop, LLM tools). Exposes 5 tools: `sandbox_create`, `sandbox_exec`, `sandbox_stop`, `sandbox_traces`, `sandbox_policy_check`. JSON-RPC 2.0 over stdio.
- **Python SDK** — Client library (`agent_sandbox` package) with async support, full API coverage, typed models, and comprehensive test suite (508 LOC).
- **Interactive Demo Examples** — Three runnable examples (demo, coding-agent, web-scraper) showcasing sandbox capabilities with colorful terminal output.
- **Role-Based Access Control (RBAC)** — 4 roles (admin, operator, viewer, agent) with 8 granular permissions. All API endpoints protected with `RequirePermission` middleware.
- **Prometheus Metrics** — `/metrics` endpoint exposing sandbox creation, action execution, policy evaluation, and API request metrics with histogram latencies.
- **Swagger/OpenAPI Documentation** — Auto-generated API documentation at `/swagger/*`.
- **Metrics Middleware** — Request-level Prometheus instrumentation for all API routes.
- **CLI Integration Tests** — Full test coverage for CLI subcommands (create, list, start, exec, trace, stop, policy validate).

### Improvements
- API coverage improved from 69.0% to 78.4% (+9.4pp)
- Trace coverage improved from 87.4% to 88.5%
- Sandbox coverage improved from 86.2% to 86.8%
- Added 27 new tests (225 → 252)
- 12 new Go source files

### New Packages
- `mcp/` — MCP server implementation (2 files, ~18KB)
- `pkg/metrics/` — Prometheus metrics collectors
- `docs/swagger/` — OpenAPI specification
- `sdk/python/` — Python SDK client library
- `examples/` — 3 interactive demo programs

## Known Limitations

1. **OS-level sandbox isolation not fully wired** — Namespace/cgroup isolation scaffolded but not production-ready
2. **MCP server has no test coverage** — Functional but untested; relies on manual testing
3. **Prometheus metrics package at 0% coverage** — Init function and collectors not unit tested
4. **No persistent user/role store for RBAC** — Roles derived from JWT claims; no user management API
5. **Python SDK not published to PyPI** — Installable from source only
6. **Web dashboard lacks E2E tests** — Component tests exist but no Playwright/Cypress integration
7. **SQLite-only trace storage** — No distributed backend option (e.g., PostgreSQL, ClickHouse)
8. **Windows-only development validated** — Cross-platform CI not fully tested

---

## Recommendations for v0.4.0

### Priority 1: Production Hardening
1. **Wire OS-level isolation** — Complete Linux namespace/cgroup integration for true sandbox isolation
2. **MCP server tests** — Add comprehensive test coverage for all 5 MCP tools
3. **Persistent user store** — Add user management API with database-backed role assignments
4. **JWT refresh tokens** — Implement token refresh flow for long-lived sessions

### Priority 2: Testing & Quality
5. **Metrics package tests** — Cover Prometheus counter/histogram registration and middleware
6. **Web E2E tests** — Add Playwright tests for dashboard, trace viewer, policy editor
7. **Cross-platform CI** — Add Linux and macOS to GitHub Actions matrix
8. **Load/stress testing** — Validate performance under concurrent sandbox execution

### Priority 3: Scale & Ecosystem
9. **Publish Python SDK to PyPI** — Package and release with proper versioning
10. **Distributed trace backend** — PostgreSQL or ClickHouse adapter for production-scale traces
11. **Plugin system** — Allow custom policy rules and executor extensions
12. **Kubernetes operator** — CRDs for sandbox lifecycle management in K8s clusters
13. **Additional SDKs** — TypeScript/Node.js and Go client libraries
14. **Webhook notifications** — HTTP callbacks for sandbox events and policy violations
